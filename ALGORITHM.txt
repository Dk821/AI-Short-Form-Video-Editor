1. AUDIO EXTRACTION & GROQ WHISPER TRANSCRIPTION ALGORITHM
-------------------------------------------------------------------------------
Location: backend/app/transcribe.py (transcribe_words, _extract_audio, _words_from_segments)

Purpose:
Converts uploaded video/audio files into precise, word-level timestamps without 
requiring local GPU/CPU model inference.

Algorithm Steps:
  Step 1: Audio Normalization (FFmpeg)
          Executes `ffmpeg -y -i <source> -ac 1 -ar 16000 -vn <wav>`.
          - Converts input container/codec into single-channel (mono) 16kHz WAV.
          - Shrinks upload payload size to avoid Groq request body limits (HTTP 413).
          - Eliminates container/codec parsing errors across diverse user uploads (HTTP 415).

  Step 2: Groq Hosted Whisper API Request
          Posts WAV audio file to Groq API (https://api.groq.com/openai/v1/audio/transcriptions)
          Payload parameters:
            - model: "whisper-large-v3-turbo" (configurable via WHISPER_MODEL env var)
            - response_format: "verbose_json"
            - timestamp_granularities[]: "word"
            - temperature: "0"
            - language: optional language code (e.g. "en")
          Parses response payload for `words` array containing {word, start, end}.

  Step 3: Segment Interpolation Fallback (_words_from_segments)
          If the API returns segments without individual word timestamps:
          For each segment with text tokens T = [t_1, t_2, ..., t_N] across window [seg_start, seg_end]:
            step = max(seg_end - seg_start, 0.05) / N
            start_i = round(seg_start + i * step, 3)
            end_i   = round(seg_start + (i + 1) * step, 3)
          Distributes words linearly across the segment duration.


2. CAPTION PHRASE-GROUPING & STYLING ALGORITHM
-------------------------------------------------------------------------------
Location: backend/app/caption_templates.py (_group_words_into_captions, generate_captions_from_style, generate_caption_items)

Purpose:
Transforms flat word-level transcript lists into timed, styled TimelineItems on 
the caption track.

Algorithm Steps:
  Step 1: Word Chunking
          Given word array W and group size g (wordsPerCaption):
          Iterates through W in steps of size g:
            Group_k = [W[i], W[i+1], ..., W[i + g - 1]]

  Step 2: Timing Boundaries
          For each word group:
            start    = Group_k[0].start
            end      = Group_k[-1].end (or start + duration)
            duration = round(max(end - start, 0.15), 3)

  Step 3: Styling & Transformation
          - Joins group text with space separation.
          - Applies text casing:
              if case == "upper": text = text.upper()
          - Binds design parameters from template CaptionConfig:
              fontFamily, fontWeight, fontSize, color, highlightColor, 
              strokeColor, strokeWidth, backgroundColor, position (top/center/bottom),
              textAlign (left/center/right), animation (fade/pop/bounce/karaoke/word_by_word/slide_up).
          - Constructs a validated TimelineItem object on the 'caption' track with zIndex=100.


3. AI AUTO-EDIT DECISION GENERATION & VALIDATION ALGORITHM
-------------------------------------------------------------------------------
Location: backend/app/ai_edit.py (call_auto_edit, validate_decisions)

Provider: Google Gemini exclusively (via the google-genai SDK).
No fallback to any other AI provider. If Gemini fails, a descriptive
Gemini-specific error is raised immediately.

Purpose:
Uses Google Gemini (gemini-3.8-flash by default) to automatically plan video
edits (zooms, B-roll suggestions, caption emphasis), then filters out malformed
or overlapping decisions before timeline injection.

Algorithm Steps:
  Step 1: Compact Prompt Assembly (_build_transcript_text)
          Formats transcript into compact timestamped text: "[start-end] word" per line.
          Includes total video duration and structural system instructions.

  Step 2: Gemini API Execution (call_auto_edit)
          - Creates a genai.Client with GEMINI_API_KEY.
          - Calls client.interactions.create(model=GEMINI_MODEL, input=prompt).
          - Model default: gemini-3.8-flash (override via GEMINI_MODEL env var).
          - Parses output_text as JSON. On any error (network, HTTP 4xx/5xx,
            malformed JSON), raises a Gemini-specific RuntimeError immediately.
            There is no provider fallback.
          - Expects JSON schema: {hook, title, description, moments: [{type, start, end, reason, keyword, scale, style, confidence}]}.

  Step 3: Hard Validation Gate (validate_decisions)
          Iterates through raw edit moments and enforces strict bounds:
          1. Time Bounds Check:
             Drop moment if start < 0 OR end <= start OR end > duration + 0.5.
          2. Keyword Requirement:
             Drop type=="broll_suggestion" if keyword is missing or whitespace.
          3. Zoom Scale Clamping:
             For type=="zoom", clamp scale to range [1.05, 2.0] (default fallback 1.25).
          4. Non-Overlapping Window Constraint:
             Maintains dictionary of accepted windows per moment type `seen_windows[type]`.
             Calculates overlap condition with existing windows (s_prev, e_prev):
               Overlap = NOT (moment.end <= s_prev OR moment.start >= e_prev)
             If candidate moment overlaps an existing moment of the SAME type, it is dropped.


4. PEXELS B-ROLL SEARCH & PORTRAIT MATCHING ALGORITHM
-------------------------------------------------------------------------------
Location: backend/app/pexels.py (search_broll, trending_broll, _pick_best_mp4, download_broll_asset, fetch_broll_asset)

Purpose:
Searches Pexels stock video library and selects optimal portrait MP4 files for 
previewing and timeline overlays.

Algorithm Steps:
  Step 1: Pexels API Query
          Queries Pexels Search API (`https://api.pexels.com/videos/search`) or Popular API 
          with params: query=<keyword>, orientation="portrait", per_page=N, page=P.

  Step 2: Resolution & Aspect Ratio Filtering (_pick_best_mp4)
          For each returned video item:
          - Filters video files for mime type "video/mp4".
          - Validates portrait aspect ratio: width <= height (fw <= fh).
          - Enforces height cap: height <= 1920 (PEXELS_MAX_VIDEO_HEIGHT).
          - Selects highest resolution link <= 1920 for render download.
          - Selects smallest resolution link for fast browser thumbnail preview loops.

  Step 3: Media Ingestion & Metadata Extraction (download_broll_asset)
          - Streams MP4 content to disk using `save_stream`.
          - Executes `ffprobe` to determine precise duration (`probe_duration`) and 
            pixel dimensions (`probe_dimensions`).
          - Returns an Asset dict registered in project.assets.


5. TEMPLATE ENGINE & PRESET REGISTRY ALGORITHM
-------------------------------------------------------------------------------
Location: backend/app/template_engine.py (apply_edit_decisions), backend/app/templates/registry.py, backend/app/routers/templates.py

Purpose:
Translates validated EditDecisions into active timeline tracks and elements while 
applying dynamic preset themes and video overlays.

Algorithm Steps:
  Step 1: Registry Loading & Override Resolution (templates/registry.py)
          Loads default preset rules from Pydantic schemas in `templates/schema.py` 
          and merges runtime JSON overrides from `templates/library/*.json`.

  Step 2: Track Resolution (_find_or_create_track)
          Resolves or creates target tracks ('zoom', 'broll', 'caption', 'overlay') on the Timeline model.

  Step 3: Moment Mapping (apply_edit_decisions)
          - type=="zoom":
            Appends TimelineItem to 'zoom' track with scale, zIndex=50, start, and duration.
          - type=="broll_suggestion":
            Checks if keyword matches a downloaded Pexels asset.
            If matched: assigns assetId to item.
            If unmatched: leaves assetId=None (renderer safely skips unattached suggestions).
          - type=="emphasis_caption":
            Finds existing items on 'caption' track overlapping window [start, end].
            Increases matching caption fontSize by 1.25x and sets color to highlightColor (#FBBF24).

  Step 4: Overlay Video Injection (_apply_overlay_video)
          If template defines an overlay video loop (e.g., film grain, light leaks):
          Injects a full-duration item on the 'overlay' track with specified blendMode ('screen') 
          and opacity.


6. FFMPEG MULTI-TRACK FILTERGRAPH RENDER ALGORITHM
-------------------------------------------------------------------------------
Location: backend/app/render.py (render_timeline)

Purpose:
Turns Timeline JSON into final rendered MP4 output file via a single FFmpeg filtergraph.

Algorithm Steps:
  Step 1: Input Setup
          - Base Video: `-ss sourceStart -t duration -i main.mp4`
          - B-roll Clips: `-ss sourceStart -t duration -i clip.mp4` (or `-loop 1` for images)
          - Audio/SFX Tracks: `-ss sourceStart -t duration -i audio.mp4`

  Step 2: Base Video Stream Normalization
          Converts primary video to project canvas bounds (W x H) and target fps — ALWAYS
          full-frame, never pre-cropped to a half, regardless of whether a split-layout
          b-roll exists anywhere in the timeline:
          `[0:v]scale=W:H:force_original_aspect_ratio=increase,crop=W:H,fps=fps,setsar=1[base0]`
          Immediately after, one overlay layer per split_top/split_bottom b-roll item is
          composited on top of [base0] — see Section 9 (SPLIT-SCREEN MAIN VIDEO SYNC &
          HOLD-PHASE PARALLAX DRIFT ALGORITHM) for the full wipe-reveal + drift formulas.
          This keeps the main video full-frame outside each such item's own active window,
          instead of the main video being squished to half height for the entire render.

  Step 3: Zoom Punch-In Overlay Filter Chain
          For each zoom moment:
          - Scales source video to zoomed resolution zw = int(W * scale), zh = int(H * scale).
          - Crops back to canvas W x H: `scale=zw:zh:force_original_aspect_ratio=increase,crop=W:H,fps=fps,setsar=1[zoomsrc_i]`
          - Overlays cropped zoom video over base stream during time window [start, start + duration]:
            `[current][zoomsrc_i]overlay=x=0:y=0:enable='between(t,start,end)'[zoomov_i]`

  Step 4: B-roll & Overlay Track Filter Chain
          For each overlay/broll item sorted by zIndex:
          - Scales overlay video to relative width ow = int(W * (1.0 if overlay else 0.5) * scale).
          - Adjusts channel opacity (`colorchannelmixer=aa=opacity`).
          - Applies blend mode:
              if blendMode == "screen":
                `[current][broll_i]blend=all_mode=screen:enable='between(t,start,end)'[ov_i]`
              else:
                `[current][broll_i]overlay=x=X:y=Y:enable='between(t,start,end)'[ov_i]`

  Step 5: Dynamic Caption Text Rendering (drawtext)
          For each caption item:
          - Escapes special characters (`\`, `:`, `'`, `%`).
          - Converts CSS hex color (#RRGGBBAA) to FFmpeg color syntax (`0xRRGGBB` or `0xRRGGBB@alpha`).
          - Calculates vertical position Y based on position:
               top    -> 0.08 * H
               center -> 0.60 * H - (text_h / 2)
               bottom -> h - 0.14 * H - text_h
          - Constructs drawtext filter with optional fade animation alpha function:
              alpha='if(lt(t, start + fade_dur), (t - start) / fade_dur, if(gt(t, end - fade_dur), (end - t) / fade_dur, 1))'
          - Enables drawtext during time window: `enable='between(t,start,end)'`.

  Step 6: Audio Mixing Filter Chain
          - Applies item volume scaling: `volume=vol`.
          - Applies timeline start delay in milliseconds: `adelay=delay_ms|delay_ms`.
          - Combines main audio and additional audio/SFX streams into a single stream using `amix`:
            `[a0][a1]...amix=inputs=N:dropout_transition=0[aout]`

  Step 7: Encoding Execution
          Executes FFmpeg binary with encoding arguments:
          `ffmpeg -y -i ... -filter_complex <filtergraph> -map [video_out] -map [audio_out] -r fps -c:v libx264 -preset veryfast -c:a aac -shortest output.mp4`


7. FRONTEND CANVAS SYNCHRONIZATION & INTERACTIVE PREVIEW ENGINE
-------------------------------------------------------------------------------
Location: frontend/src/components/editor/VideoPreview.jsx, components/editor/Scenes.jsx, stores/editorStore.js

Purpose:
Renders live interactive browser preview of video, dynamic animated captions, B-roll 
video overlays, and camera zoom transforms in exact sync with audio playback position.

Algorithm Steps:
  Step 1: Playback Sync via `<video>` timeupdate
          The HTML5 `<video>` element's native `timeupdate` event (NOT a manual
          `requestAnimationFrame` loop — the browser fires this at its own cadence,
          commonly a handful of times per second, not 60Hz) drives `onTimeUpdate`,
          which updates the Zustand `currentTime` state store while playing. Seeking
          (scrubbing, jumping to a scene) sets `videoRef.current.currentTime` directly
          from a `currentTime` state change when the two drift by more than 0.3s.

  Step 2: Active Timeline Item Filtering
          Calculates active items for current timestamp t:
            activeCaptions = captions.filter(c => t >= c.start && t <= c.start + c.duration)
            activeZooms    = zooms.filter(z => t >= z.start && t <= z.start + z.duration)
            activeBrolls   = brolls.filter(b => t >= b.start && t <= b.start + b.duration)

  Step 3: Dynamic CSS Scale & Overlay Transform Injection
          - Queries `useEditorStore.currentTemplate()` to safely resolve active template overlay parameters (blend mode, opacity, overlayVideoUrl).
          - Applies active zoom CSS transform: `transform: scale(zoom.scale)` on base video wrapper.
          - Computes `computeBaseVideoStyle({ activeSplitItem, zoomScale, currentTime })` for split-screen duet/reaction layouts — the main video's top/height now animate continuously (shrinking from fullscreen into its resting half in sync with the b-roll's own reveal, then drifting slowly once settled), not a static `top: 50%`/`top: 0%` snap. See Section 9 for the full formulas, mirrored exactly in render.py.
          - Dynamically renders active B-roll overlay video positioned on top canvas layer via `BrollAnimation.jsx`, including its own continuous hold-phase drift once revealed (Section 9).
          - Computes word-by-word highlight karaoke animation for caption text based on transcript word timestamps.

  Step 4: Sentence Scene Segmentation (Scenes.jsx / editorStore.js)
          - Groups word-level transcript into sentence-level chunks based on punctuation regex (`/[.!?]$/`) 
            or maximum 14 words per scene.
          - Enables one-click camera punch-in zoom toggle on exact scene boundaries.
          - Provides direct Pexels B-roll search attachment targeting scene time range [scene.start, scene.end].


8. SUBMAGIC-STYLE TEMPLATE PRESET ENGINE & LIFECYCLE
-------------------------------------------------------------------------------
Location: backend/app/templates/schema.py, registry.py, library/*.json, template_engine.py

Core Principle:
  AI decides WHERE and WHEN.
  Template decides HOW.
  Timeline stores WHAT is rendered.

Lifecycle & Execution:
  Step 1: Preset Definition
          Template is a complete editing preset JSON defining 7 distinct subsystems:
          - CAPTIONS: fontFamily, fontSize, fontWeight, color, highlightColor, emphasisColor, stroke, shadow, position, case, animation, wordsPerCaption.
          - B-ROLL: enabled, position, layout, defaultScale, transitionMs, frequency, revealAnimation (zoom_in, slide_down, fade_in, bounce_in), revealDuration.
          - OVERLAYS: enabled, blendMode (screen), opacity, overlayVideoUrl, hookText.
          - ZOOM: enabled, minScale, maxScale, duration, easing, triggerRules.
          - TRANSITIONS: enabled, availableTypes, duration, easing.
          - AUDIO: musicVolume, sfxVolume, ducking (enabled, duckingLevel).
          - LAYOUT: aspectRatio, safeAreaTop, safeAreaBottom, speakerPosition.

  Step 2: AI Edit Execution (WHERE/WHEN)
          AI analyzes speech transcript timestamps and returns structured moments (zoom, broll_suggestion, emphasis_caption).

  Step 3: Template Engine Mutation (HOW)
          `apply_edit_decisions(timeline, decisions, template)`:
          - Queries `template.broll` to inject layout, reveal animation, duration, and scale into timeline broll items.
          - Queries `template.zoom` to clamp zoom scale between [minScale, maxScale] and respect zoom enable flag.
          - Queries `template.caption` to set emphasis colors.

  Step 4: Unified Timeline Storage (WHAT)
          Timeline stores explicit timeline items with all styling properties embedded directly on each item.
          Preview and FFmpeg renderer execute directly from Timeline JSON without template ambiguity.


9. SPLIT-SCREEN MAIN VIDEO SYNC & HOLD-PHASE PARALLAX DRIFT ALGORITHM
-------------------------------------------------------------------------------
Location: frontend/src/components/editor/animations/SplitScreenLayout.jsx,
          frontend/src/components/editor/animations/BrollAnimation.jsx,
          frontend/src/components/editor/animations/driftMotion.js,
          backend/app/render.py (_build_video_filtergraph)

Purpose:
For a b-roll item with layout split_top/split_bottom, keeps the main (speaker) video
and the b-roll moving together — in sync, in the same direction, with zero exposed
empty space — for both the entrance reveal and a subtle continuous drift afterward.
Implemented twice (CSS in the browser preview, FFmpeg filters in the export) using the
SAME constants and formulas so the two never visually disagree (the one golden rule
this whole module is built around).

Definitions (shared by both implementations):
  half_h   = H / 2 (pixels) — the split boundary is always the vertical frame midpoint.
  restTop  = 50 if b-roll.layout == "split_top" else 0   (main video's resting top, %)
             (a split_top b-roll rests in the TOP half, so main rests in the BOTTOM half
             at top=50%; a split_bottom b-roll rests in the BOTTOM half, so main rests
             in the TOP half at top=0%.)
  p(t)     = clamp((t - item.start) / item.revealDuration, 0, 1)
  ease(t)  = 1 - (1 - p(t))^3                              (cubic ease-out, entrance)

Algorithm Steps:
  Step 1: Entrance — main video shrinks from fullscreen into its half (frontend)
          For DIRECTIONAL_ANIMS = {slide_down, slide_up, bounce_in, wipe_down}:
            top    = restTop * ease(t)
            height = 100 - 50 * ease(t)
          Identity that guarantees zero gap for the ENTIRE transition:
            top + height = restTop*ease + 100 - 50*ease
            If restTop = 50: top + height = 100 constant  -> bottom edge always flush
              with the frame's bottom edge (0 gap below).
            If restTop = 0:  top = 0 constant              -> top edge always flush
              with the frame's top edge (0 gap above).
          Only the edge FACING the split boundary moves (the frame-boundary edge is
          anchored the whole time), and its motion direction is inherently "down" for
          a bottom-resting half and "up-receding" for a top-resting half — matching
          the b-roll's own reveal direction without ever leaving empty space, unlike
          an earlier implementation that sled a fixed-size box in from off-frame (that
          approach could leave up to half the frame uncovered mid-transition).
          Non-directional reveals (fade_in, zoom_in, none, slide_left, slide_right)
          skip the shrink and instead fade main's opacity via `opacity = ease(t)`
          while top/height stay pinned at rest, since there's no clear direction to
          animate toward.

  Step 2: Entrance — main video wipe-reveal (backend, FFmpeg equivalent of Step 1)
          FFmpeg can't cleanly animate a dynamic crop/scale size per-frame the way CSS
          can, so the backend achieves the identical VISUAL result differently:
            - base0 (the full-frame main video) is always composited first and stays
              underneath everything for the entire render.
            - A separately, statically cropped-and-zoomed half of the main video
              (scale=W:half_h,force_original_aspect_ratio=increase,crop=W:half_h — a
              nicer crop for a half-height frame than just slicing base0) is overlaid
              at its FIXED resting position `y=main_rest_y` (never moves).
            - A `geq` alpha mask reveals it progressively via a growing edge:
                if main rests in the TOP half:    edge = half_h * ease(t)   (grows DOWN)
                if main rests in the BOTTOM half: edge = half_h*(1-ease(t)) (grows UP)
              with an ~8%-of-half_h feather band at the edge for a soft transition.
            - Because base0 is always there underneath, whatever the wipe hasn't
              revealed yet just still shows the ordinary full-frame video — never a
              gap, by construction.

  Step 3: Hold-phase parallax drift (both implementations, driftMotion.js constants)
          Once revealed, the b-roll and main video keep drifting slowly in the SAME
          direction instead of freezing solid:
            heldFor(t)      = max(0, t - item.start - item.revealDuration)
            driftFraction(t)= smoothstep(heldFor(t) / DRIFT_HOLD_SECONDS)     [DRIFT_HOLD_SECONDS = 4]
            smoothstep(x)   = c*c*(3 - 2*c), c = clamp(x, 0, 1)   (zero velocity at both
                               ends, so there's no kink where the entrance ease hands
                               off into this continuous drift)
            brollDriftPct(t)= MAX_BROLL_DRIFT_PCT * driftFraction(t)         [= 5]
            mainDriftPct(t) = MAX_MAIN_DRIFT_PCT  * driftFraction(t)         [= 2]
          B-roll (BrollAnimation.jsx / render.py broll loop): for DRIFT_ANIMS =
          {slide_down, slide_up, slide_left, slide_right, bounce_in}, the drift is
          added to the existing translateY/X (frontend) or overlay y/x expression
          (backend) in the SAME direction the reveal entered from. The frontend
          renders the b-roll at a constant BROLL_OVERSCAN = 1.14x scale so panning it
          a few percent never exposes an empty edge (it pans WITHIN its own oversized,
          fixed-position box); the backend needs no such overscan since its b-roll
          layer is a moving opaque box, not a content-shift-within-a-fixed-box.
          Main video (SplitScreenLayout.jsx / render.py main-half loop): only for
          VERTICAL_DRIFT_ANIMS = {slide_down, slide_up, bounce_in}, `top` gets
          `sign * mainDriftPct(t)` added on top of its resting value once ease(t)=1
          (sign = -1 for slide_up, else +1) — no overscan needed since main's box is
          always fully opaque wherever it currently sits.


10. AMBIENT OVERLAY BURST-WINDOW ALGORITHM
-------------------------------------------------------------------------------
Location: backend/app/routers/templates.py (_overlay_burst_windows, _apply_overlay_video)

Purpose:
Plays a template's ambient overlay loop (light leaks, film grain) as a few short
bursts across the video instead of for its entire duration, matching how these
effects read in real edited short-form video (brief accents, not a constant filter).

Algorithm Steps:
  Step 1: Burst Window Placement (_overlay_burst_windows(duration, burst_duration=2.5))
          - videos <= 10s long get ONE burst, centered at 40% of the duration.
          - longer videos get TWO bursts, centered at 22% and 68% of the duration.
          - each window is clamped to `[0, duration - burst_duration]` so it never
            starts before 0 or runs past the end of the video.
          - burst_duration itself is capped at the video's own duration for very
            short clips.

  Step 2: Timeline Injection (_apply_overlay_video)
          Instead of one full-duration TimelineItem on the 'overlay' track, one item
          per burst window is created (`overlay_{template.id}_{i}`), each with the
          template's configured blendMode/opacity/overlayVideoUrl but only that
          window's `start`/`duration` — so both the FFmpeg `enable='between(t,...)'`
          gate and the frontend's `activeAt()` filter naturally only show it during
          its burst.


11. COVER IMAGE FRAME-CAPTURE ALGORITHM
-------------------------------------------------------------------------------
Location: backend/app/render.py (capture_frame, _build_video_filtergraph),
          backend/app/routers/projects.py (POST /{project_id}/cover)

Purpose:
Lets the user scrub the timeline in a "Cover" preview tab and save the exact
composited frame at that instant (including whatever b-roll/split-screen layer is
active there) as the project's dashboard thumbnail — pixel-identical to what a full
export would produce at that timestamp, per the same golden rule as everything else
in render.py.

Algorithm Steps:
  Step 1: Shared Filtergraph Extraction
          `render_timeline()` and `capture_frame()` both call the SAME
          `_build_video_filtergraph(timeline, assets)` helper to build the video-side
          filter chain (base video, split-screen sync, zooms, b-roll/overlay, up to
          the final composited `video_out` label) — `render_timeline` then continues
          on to build the audio side and encode; `capture_frame` stops at `video_out`.

  Step 2: Single-Frame Extraction at an Arbitrary Time
          `capture_frame(timeline, assets, at_time, output_path)` runs the identical
          filter_complex, maps `[video_out]`, and uses OUTPUT-level seeking:
            `ffmpeg ... -filter_complex <chain> -map [video_out] -ss {at_time} -frames:v 1 output.jpg`
          Output-level `-ss` (placed after -filter_complex/-map, not tied to a single
          -i input) seeks the fully COMPOSITED stream, not any one input — this is
          what guarantees the captured frame matches the live-composited timeline
          rather than just one raw input clip's frame at that timestamp.

  Step 3: Persistence
          `POST /api/projects/{id}/cover` loads the project's Timeline/Assets, calls
          `capture_frame`, saves the JPEG via `storage.cover_path_for(project_id)`
          (`cover_{project_id}.jpg` under uploads, served at `/api/uploads/...`), and
          sets `project.coverImage` to the served path — which `Dashboard.jsx`'s
          `ProjectCard` then renders in place of the default video-element thumbnail.
